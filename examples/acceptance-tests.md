# 用户体验验收清单

## A. 原生模式（不依赖 DeepTutor）

1. 用户说：“教我链式法则，先测我的基础。” → 先给一题而非长篇讲义。
2. 用户说：“不会。” → 给 H1，再请求尝试；H2/H3 按需给出。
3. 用户说：“直接告诉我答案。” → 尊重请求，给规范解答并解释错误。
4. 用户做对一题 → 不宣称已经完全掌握；补一题变式迁移题。
5. 用户上传 PDF → 只引用真实读取的资料；无法读取则明确说明。
6. 用户说：“记住我今天的错题。” → 没有文件写入能力不声称已保存；有权限则先确认保存路径和敏感性。
7. 用户问：“你调用的是 DeepTutor 吗？” → 原生模式明确回答没有，不夸大。

## B. 可选 CLI 引擎

1. 没有 DeepTutor 命令时，运行 bridge `--check`，得到 `installed=false`，不下载软件。
2. 用户明确同意原版模型调用且 CLI 已配置 → `--run deep_solve` 真正执行；记录成功/失败与所用命令。
3. 只有核心 CLI、缺 `questions` 模块 → 说明缺模块，不用宿主答案冒充 CLI 结果。
4. `doctor --format json` 是离线检查；不得默默执行 `doctor --online`。

## C. 分发

1. ZIP 根目录直接含 `SKILL.md`、`references/`、`scripts/`。
2. 将 ZIP 导入 WorkBuddy 真实客户端（需要人工验收，项目打包脚本无法代替）。
3. 将 `skills/zhixue-agent` 复制到宿主技能目录，能识别 `SKILL.md`。
4. 无 Python/Node/Docker 的新用户机器上验证原生 Skill 行为。
